# Заказ 01. Машинные проверки: код 0 при нарушении правила

Файлы: `scripts/check_workspace.py`, `scripts/verify_canon.py`, `scripts/verify_sandbox.py`, `rules/canon.json`.

Метод проверки каждого пункта: собрать временный корень с `workspace/`, вызвать
`python scripts/check_workspace.py --root <корень>` (или соответствующую проверку) и сравнить код с ожидаемым. Корень удалить после.

## A1. Артефакт сверяется с полем состояния, а не с исходом отчёта ворот

- Сейчас: `scripts/check_workspace.py:276` сравнивает `state_gate` с `report_outcomes`; в блоке артефакта сверки с исходом отчёта нет.
- Факт: отчёт ворот «заблокировано» + `state.md` «Исход ворот: прошло» + `artifact.md` → код 0.
- Нужно: в блоке артефакта — если существует отчёт ворот с исходом ≠ «прошло», артефакт считается нарушением (кроме внутреннего контура).
- Проба: 3 файла (`state`, `research/prevalidation-*.md` с «заблокировано», `artifact.md`) → ожидать 1.

## A2. `workspace/artifacts/*` не читается

- Сейчас: проверка знает только `workspace/artifact.md`.
- Факт: `workspace/artifacts/расчёт-v3.md` со статусом «показан человеку» без судьи и состояния → код 0.
- Нужно: либо читать все `workspace/artifacts/**/*.md` по тем же правилам, либо в `skills/04-mvp-artifact` оставить единственный носитель статуса/версии — `artifact.md`, а отдельные файлы считать вложениями без статуса (тогда добавить правило в `templates/README.md`).
- Проба: оба варианта → ожидать 1 на файле со статусом «показан человеку».

## A3. Артефакт без `state.md`

- Сейчас: при отсутствии состояния пропускаются сверки версий и решений.
- Факт: `artifact.md` (черновик, версия 1) без `state.md` → код 0.
- Нужно: наличие артефакта требует `state.md`; отсутствие — нарушение.
- Проба: только `artifact.md` → ожидать 1.

## A4. Пакеты и факты ворот

- Сейчас: `scripts/check_workspace.py:245` извлекает только `N`; `M` не сверяется; текст вопроса не проверяется.
- Факты: «Пакет: 1 из 99» → 0; «Пакет: 0 из 1» → 0; «Пакет: 2 из 1» → 0; строка `Q1.1` с пустым вопросом → 0.
- Нужно: `N ≥ 1`, `M ≥ 1`, `N ≤ M`; `Q`-идентификаторы фактов только пакета `N`; в каждой строке факта непустой текст вопроса; два факта — два разных непустых вопроса.
- Проба: 5 фикстур → все ожидают 1.

## A5. Ответы

- Сейчас: `scripts/check_workspace.py:232–235` требует длину ≥100 и `Q\d+`.
- Факты: две побайтно одинаковые копии ответа → 0; файл из 100 символов мусора → 0.
- Нужно: уникальность хэшей файлов ответов; ≥2 разных `Q`; текст без заглушек («ответов нет», «не знаю»), минимум 200 знаков; читать и `workspace/responses/`, и `workspace/responses/inbox/`.
- Проба: 3 фикстуры → ожидать 1.

## A6. Предел, удалённый вместе с ключом

- Файл: `rules/canon.json`, блок `limits_where`.
- Факт: удалить ключ `questions_later` из `limits_where`, поставить в `AGENTS.md` «не больше семи» → `python scripts/verify_canon.py` возвращает 0.
- Нужно: в канон добавить список обязательных ключей (`limits_required` с теми же 19 именами); пропуск ключа — код 1.
- Проба: копия канона без ключа → ожидать 1.

## A7. Песочница: удаление и подмена

- Файл: `scripts/verify_sandbox.py`.
- Факты: `rm -rf runs` → код 0 «копии нет»; `runs/self-01` как ссылка на корень теперь ловится (`:61`), но удаление — нет.
- Нужно: если каталога `runs/` нет, а есть `internal/draft/` (режим разработки) — код 2 «копия не сверена». Для чистой копии пользователя без `internal/` — код 0.
- Проба: удалить `runs` в репозитории разработки → ожидать 2; в копии без `internal/` → 0.

## A8. Заглушка проверки

- Файл: `scripts/verify_canon.py:114`.
- Факт: файл с докстрингом 1600 знаков, строкой «ИТОГ:» и `def main(): return 0` проходит порог.
- Нужно: добавлять проверку логики (наличие `sys.exit(`, минимум двух `if`, вызовов `open(`/`read(`), либо сверять эталонный хэш каждого скрипта из списка канона.
- Проба: заглушка + `sync` песочницы → ожидать 1.

## A9. Самопроверки покрывают не всё

- Файлы: `scripts/check_workspace.py` (`--self-test`), `scripts/verify_canon.py`, `scripts/verify_sandbox.py`.
- Сейчас: `--self-test` собирает только `state` + отчёт ворот; у двух других скриптов флага нет.
- Факты, которые не ловятся: регресс в блоках judge-report / artifact / decisions; регресс в проверке песочницы.
- Нужно: в `--self-test` добавить фикстуры «полный корректный комплект» (state, отчёт ворот, ответы, отчёт судьи, артефакт, решения) и 2–3 испорченных; добавить `--self-test` в два оставшихся скрипта.
- Проба: `python scripts/check_workspace.py --self-test` → 0; испортить судью → 1.

## A10. Битый канон в одиночном запуске

- Файл: `scripts/verify_canon.py`.
- Факт: удалить блок `limits` → `KeyError`, трейсбек, код 1 без строки «ИТОГ:».
- Нужно: `try/except` вокруг чтения и проверок → «ИТОГ: 2 — канон сломан».
- Проба: копия канона без блока → ожидать 2.

## Критерий приёмки заказа

Все 10 проб дают ожидаемые коды; `python scripts/verify.py` → 0; песочница синхронизирована. Отчёт — таблица «пункт → проба → код до → код после».
