# Реестр запросов внешнему исследователю

## Правила

1. **Каждый запрос самостоятелен.** Отдельный файл, который уходит внешней модели без нас: внутри есть границы, контракт и структура ответа. Ссылок на другие запросы быть не может — соседей модель не увидит.
2. **Собран по шаблону:** `templates/request-short.md` (до пяти вопросов, один канал) или `templates/request-full.md` (до шести вопросов, минимум два канала).
3. **Своя нумерация** от `Q1.1` внутри файла, подряд, не больше шести вопросов. Ожидаемый ответ — до 2500 слов.
4. **Ответ** кладётся в `workspace/responses/<имя запроса>.answer.md` (для проектных запросов — в `internal/draft/responses/`).

Проверки:

```
python scripts/verify_requests.py   # структура и самостоятельность
python scripts/verify_research.py   # полнота ответов
```

## Объём: короткий или полный

Метка в заголовках разделов ниже — это объём запроса, а не важность темы. Само правило выбора живёт в одном месте: `skills/03-prevalidation/SKILL.md`, раздел «Объём запроса». Здесь только метки и причина.

**Категория в шапке.** У каждого запроса есть строка `**Категория:**`: `быстрая` для короткого объёма и `дип` для полного. По ней видно, в каком режиме внешнего сервиса запускать: быстрый поиск или глубокое исследование. Это метка режима, а не второй метод — внутри одна предвалидация с разным объёмом.

| Метка | Размер | Зачем такой | Где сейчас |
|---|---|---|---|
| короткий | 3–5 вопросов, один канал, до 1200 слов ответа | проверить, есть ли данные вообще, и уточнить формулировку | `req_00a`–`e` (отвечены, архив), `req_01a`–`f` (ждут) |
| полный | до пятнадцати вопросов суммарно, минимум два канала, пакетами по шесть, до 2500 слов на пакет | фактура для артефакта или чужого документа: нужны две стороны и ограничения | `req_01_integrations_a`, `req_01_integrations_b` (ждут) |

**Почему разложено именно так.**

- `req_01a`–`f` — короткие разведчики: сначала надо понять, есть ли в открытых источниках данные по теме. Если разведка покажет, что данные есть и они нужны для артефакта, по той же теме оформляется полный запрос; пакеты одного предмета не дублируются.
- `req_01_integrations_a` и `_b` — один полный запрос, разрезанный на два пакета по шесть вопросов: интеграция с прикладным софтом нужна для артефакта и для слайдов блока 2, ошибка видна заказчику.
- Цифры и ставки — отдельное правило: короткий запрос с цифрами исключение, второй канал обязателен, потому что одно число из одного источника не проверяемо. `req_00b_rates` прошёл коротким проходом и требует полного, если цифры пойдут в стрим.

**Спорные случаи.** В `req_00c_players` и `req_00d_method` часть вопросов по типу полная: сравнение сервисов, спецификация навыков, конфликты источников. Они ушли коротким проходом, потому что задача была проверить наличие данных. Если факты пойдут в стрим, по этим темам нужен полный проход.

**Состояние архива.** Пять коротких пакетов (`req_00a`–`e`) получили ответы, но **ни в одном нет прямых адресов**: названы источники и даты, ссылок ноль. По правилу «нет ссылки — нет находки» ни один факт не переведён в базу знаний; ответы лежат в `archive/answers/` со статусом «ссылки не проверены» и требуют повторного прохода с требованием адресов.

## Состояние и архив

Каждый запрос несёт в шапке строку **`**Состояние:** отвечено N из M`** — она заполняется автоматически, руками не правится:

```
python scripts/verify_state.py --write   # обновить строки состояния
python scripts/verify_state.py           # проверить, что строки сходятся с диском
```

Когда на все вопросы запроса есть ответ, пара «запрос + ответ» переносится в `archive/` (ответ — в `archive/answers/`):

```
python scripts/verify_state.py --move
```

В активной папке остаются только запросы, ждущие ответа. Архив не выпадает из проверок: структура и полнота проверяются и там.

## Как отправлять

Запросы независимы: можно отправлять параллельно и в любом порядке. Ответ приходит отдельным файлом на каждый запрос — один запрос, один ответ. Если сервис отвечает одним документом сразу на несколько запросов, ответ режется по файлам, содержимое дословное, нумерация приводится к нумерации запроса.
