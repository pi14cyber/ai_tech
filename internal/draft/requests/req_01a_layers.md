## 1. Границы

- **Предмет:** публичные стартовые наборы и методологии для внедрения ИИ-инструментов в работу конкретного человека: репозитории, фреймворки, плейбуки, внутренние регламенты компаний. Граница между неизменяемым ядром и данными пользователя.
- **География и период:** глобально, отдельный срез по русскоязычным источникам; 2024–2026 годы.
- **Что не спрашиваем:** оценки, прогнозы рынка, сравнение заказчиков между собой.

## 2. Вопросы

### Q1.1. Опубликованные примеры

Какие публичные репозитории, шаблоны проектов и фреймворки явно разделяют неизменяемое ядро и данные пользователя? Привести примеры с адресами: как называются слои, где проходит граница.

### Q1.2. Соглашения и последствия

Какие соглашения описаны для такой границы: правила именования, версионирование ядра, порядок обновления ядра при наличии пользовательских данных, миграции?

### Q1.3. Что ломается

Какие задокументированные проблемы возникают, когда универсальный слой и данные пользователя смешаны? Примеры: потери данных при обновлении, расхождение версий, невозможность передать набор другому.

### Q1.4. Нижняя граница универсальности

Есть ли в открытых источниках свидетельства, что универсальный слой должен оставаться пустым по данным, без примеров пользователя, или практика допускает примеры и заполненные образцы внутри ядра?

## 3. Контракт формата

1. **Нет ссылки — нет факта.** Каждый пример и соглашение — с прямой ссылкой и датой.
2. **Запрет прогнозов.** Только свершившиеся факты: версии, правила, записи в трекерах.
3. **Микро-факты вместо обобщений:** адрес репозитория, файл правил, номер версии.
4. **Пропущенный идентификатор считается неотвеченным.**
5. Последняя строка ответа: «Чего найти не удалось: …».

## 5. Белые пятна

Белым пятном считается только то, что искали задокументированно: каналы, формулировки, проверенные реестры, дата. «Не нашлось» без описания поиска белым пятном не считается.
