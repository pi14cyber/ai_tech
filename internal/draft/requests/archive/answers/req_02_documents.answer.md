### Q1.4. Векторизация документов и поиск по ним

**Факты за:**
  - Локальные встраиваемые векторные базы:
	  - sqlite-vec — расширение C/SQLite весом менее 1 МБ с нулевым потреблением в простое; выполняет плоский SIMD-скан (AVX2) 100 000 векторов за 5–15 мс (100k векторов размерности 1536 в 1-битной квантизации занимают всего 19,2 МБ памяти).
	  - Chroma — встраиваемый движок (PersistentClient, Apache 2.0) с HNSW-индексацией через hnswlib и хранением метаданных в SQLite, разворачивается локально без отдельного сервера.
	  - Qdrant — локальный встраиваемый/контейнерный движок на Rust с поддержкой квантизации (Scalar/Binary Quantization) и фильтрацией метаданных по графу HNSW.
  - Локальные эмбеддинг-модели: связка с nomic-embed-text-v1.5 или моделями bge-m3 через ONNX Runtime или llama.cpp позволяет полностью локализовать векторизацию без затрат на API и передачи контекста наружу.
**Факты против:**
  - sqlite-vec на больших массивах (>1–10 млн векторов) показывает падение recall из-за отсутствия сложного графового HNSW-индекса; embedded Chroma требует существенного расхода оперативной памяти при индексации графа и уступает клиент-серверным решениям при конкурентной записи. При обновлении документов удаление старых чанков требует принудительной инвалидации индекса во избежание дубликатов в выдаче RAG.

### Q1.6. Сборка итогового документа

**Факты за:**
  - Инструменты генерации:
	  - Typst — компилируемый движок вёрстки на Rust (0.14+), генерирует PDF с высокой скоростью компиляции, модульной структурой функций-шаблонов и встроенной типографикой.
	  - WeasyPrint (v68+) — генератор документов из HTML/CSS в PDF со стандартами Paged Media (@page, колонтитулы, разрывы страниц) в связке с шаблонизатором Jinja2.
	  - python-docx и docxtpl — сборка документов Word на основе Jinja-подобных тегов внутри нативного макета .docx.
  - Методы автоматической проверки сборки: сквозное тестирование макета через визуальное сравнение (visual regression testing) с помощью pdf2image и библиотеки Pillow/ImageChops (попиксельный diff страниц), проверка структурных полей через pdfplumber, а также валидация PDF/A-совместимости через утилиту verapdf.
**Факты против:**
  - Ограничения вёрстки: WeasyPrint не поддерживает выполнение JavaScript для динамических графиков (требует рендеринга графиков в статические PNG/SVG до сборки); Typst и WeasyPrint используют построчный алгоритм переносов, что в редких случаях даёт менее сбалансированное распределение межсловных пробелов по сравнению с полным алгоритмом Кнута-Пласса в TeX.
