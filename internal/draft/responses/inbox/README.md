# Входящие ответы: папка, куда кидать

**Что это.** Место, куда кладётся ответ от внешнего исследователя в том виде, в каком он пришёл: текстом из чата, файлом, экспортом, куском документа. Причёсывать и переформатировать перед тем, как положить, не нужно — это работа агента.

**Как назвать файл.**

- Ответ на конкретный пакет — `<имя запроса>.md`, например `req_02_access.md`.
- Не знаете, к какому пакету, или ответ один на несколько тем — любое понятное имя, например `2026-10-20-networking-perplexity.md`.

**Минимум в первой строке:** дата получения и канал (Perplexity, Qwen, Google, другой). Этого достаточно, остальное разберёт агент.

**Что дальше.**

1. Агент читает входящие при старте сессии; их число показывает `python scripts/verify_research.py` в строке «ВХОДЯЩИЕ».
2. Ответ нарезается по идентификаторам `Q` и превращается в структурированный файл `<имя запроса>.answer.md` в родительской папке по шаблону `templates/research-response.md`.
3. Оригинал уходит в `raw/` как след: в базу знаний идёт только выжимка с адресами, не сырой текст.
4. Полнота проверяется `python scripts/verify_research.py`. Когда ответ закрывает все вопросы, пара «запрос + ответ» уезжает в архив: `python scripts/verify_state.py --move`.
5. Факты без прямых адресов в базу знаний не переводятся: остаются `[внешнее, ссылки не проверены]` и требуют повторного прохода.

**Чего не делать.**

- Не редактировать ответ, «причёсывая» его: дословность важна для проверки.
- Не дописывать факты по памяти: чего в ответе нет, того нет.
- Не удалять оригинал после разбора: он остаётся в `raw/` как след.

## Заготовки ответов

На каждый активный запрос здесь лежит пустой файл `<имя запроса>.md` с уже расставленными блоками: по одному разделу на каждый `Q1.N`, внутри — «Факты за», «Факты против», «Белые пятна». В шапке стоит категория — `быстрая` или `дип`: по ней видно, в каком режиме запускать запрос во внешнем сервисе.

**Что делать:** открыть файл нужного запроса, вписать дату и канал, скопировать ответ модели в блоки. Ответ на каждый `Q` — в свой раздел, дословно. Если по вопросу данных нет, оставить пометку, где искали: это и есть белое пятно, а не пропуск.

**Как пересоздать.** Заготовки строятся из самих запросов, поэтому заголовки не расходятся с вопросами:

```
python scripts/make_answer_blanks.py
```

Скрипт не перезаписывает существующие файлы (заполненный ответ дороже каркаса), пропускает снятые запросы и не трогает архив. Новый пакет запросов → запустить ещё раз, появится заготовка только на него.

**Зачем пустые файлы.** Проверка полноты смотрит, есть ли в каждом блоке ссылка или пометка белого пятна. Каркас не даёт потерять вопрос: пустой блок видно сразу, а вопрос, вписанный в общий текст, — нет.
