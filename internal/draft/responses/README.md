# Ответы внешнего исследователя

Сюда складываются ответы на запросы из `internal/draft/requests/`. Имя файла: `<имя запроса>.answer.md`, например `req_00_stream.answer.md`.

**Ответы не по шаблону** (статьи, отчёты, выгрузки без идентификаторов) кладутся в `raw/` — там описано, как их обрабатывать. В общую папку их класть нельзя: проверка полноты считает файл без идентификаторов сломанной декларацией, и это верно.

**Как заполнять:** копировать `templates/research-response.md`, а не писать с нуля: в шаблоне уже расставлены блоки по идентификаторам вопросов.

**Как проверять полноту:**

```
python scripts/verify_research.py
```

Скрипт сверяет ответ с запросом по идентификаторам и сообщает:

- какие вопросы остались без ответа;
- есть ли идентификаторы, которых нет в запросе;
- есть ли обязательные разделы (факты за, факты против, белые пятна);
- в каждом ли блоке есть ссылка или пометка белого пятна.

Коды возврата: `0` — всё сходится или ответов ещё нет; `1` — ответ неполный; `2` — сломан запрос.

**Правило:** неотвеченный вопрос не додумывается. Он либо возвращается в очередь запросов, либо помечается белым пятном с указанием, где искали.

## Ответ без адресов источников

Ответ, где названы источники и даты, но **нет прямых адресов**, принимается в архив со статусом `[внешнее, ссылки не проверены]` и **в базу знаний не переводится**: по правилу «нет ссылки — нет находки» это ещё не факты. Нужен повторный проход с адресами, после чего факты идут в карточки `knowledge/02_external/`.

## Один документ на несколько пакетов

Если внешний сервис отвечает одним документом сразу на несколько пакетов, ответ режется по пакетам: файл на каждый пакет, содержимое дословное, идентификаторы не меняются. В шапке каждого файла указывается, какие вопросы в нём есть и какие остались за пределами этой части.

## Где искать ответы

Ответы на отработанные запросы лежат не здесь, а в архиве: `internal/draft/requests/archive/answers/`. Перенос делает `python scripts/verify_state.py --move`, когда на все вопросы запроса получен ответ. Строка состояния в самом запросе показывает, сколько отвечено и где лежит ответ.
