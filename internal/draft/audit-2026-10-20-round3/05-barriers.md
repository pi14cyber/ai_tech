## 3. Приёмка: что ловит `verify.py`

### 3.1. Запуски

```
python scripts/verify.py            → ИТОГ ПО ВСЕМ ПРОВЕРКАМ: 0
python scripts/verify_consistency.py → ИТОГ: 0 — числа и формы сходятся
```

Одиннадцать проверок, все «сходится»: заметки по источникам (4 источника, покрытие до конца файлов), база знаний (5 карточек), внешнее исследование (54 вопроса, 54 отвечено), структура запросов (16), состояние запросов (0 в работе, 16 в архиве), навыки (14), документация и пути (241 ссылка в 57 файлах), разделение слоёв (42 файла), ссылки в заметках (948 в 15 файлах), адаптеры (3 каталога, 42 ссылки), числа и формы (26 шаблонов, 14 навыков, 19 файлов). Режим: обычный (внешние запросы разрешены).

### 3.2. Два машинных утверждения, проверенные запуском

Проверял на копии скриптов во временной папке (`$env:TEMP`), репозиторий не менял.

1. **«Быстрая» с шестью вопросами.** Файл с `**Категория:** быстрая`, шестью `Q1.1-Q1.6` и одним каналом: `ИТОГ: 0 — все запросы собраны по шаблону и самостоятельны`. То есть предел короткого запроса (пять) не проверяется, хотя `templates/request-short.md:13` его объявляет. Узкое место — `scripts/verify_requests.py:41` `MAX_QUESTIONS = 6` и `:73-76`, где «Категория» проверяется только на наличие.
2. **Продолжение нумерации `Q` по канону.** Второй пакет `Q1.7-Q1.9` (как требует `skills/03:27`) даёт: `СТРУКТУРА: … нумерация вопросов должна идти подряд от Q1.1, сейчас Q1.7, Q1.8, Q1.9`, `ИТОГ: 1`. Правильное по канону поведение приёмка считает ошибкой.
