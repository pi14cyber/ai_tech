# Механика прогона на себе: где, как и что смотрит свежий агент

**Дата:** 20.10.2026. **Вопрос владельца:** «давай сначала технически продумаем как протестировать — мы субпапку сделаем? или как. и как агент в новой сессии поймёт что делать и как использовать скилы? в харнессе есть скилы?»

---

## 1. Факты про харнесс (проверено по сборке, не по памяти)

- **Скиллы в харнессе есть.** Это отдельный реестр (`@deepseek-ai/dsh-tool-skill`), а сами скиллы поставляются плагинами: например `@deepseek-ai/dsh-skill-office` даёт `office-docx`, `office-pptx`, `office-xlsx`, а `diagnose-windows-sandbox-acl` идёт с рантаймом. Именно они видны в каталоге сессии.
- **Источники скиллов в реестре:** `project-dsh`, `project-agents`, `runtime`, `user-dsh`, `user-agents`, `custom`, `bundled`.
- **Проектный каталог существует:** `<корень проекта>/.dsh/skills`, приоритет 100. Есть также агентские каталоги (`project-agents`), то есть оболочка умеет читать раскладку вида `.agents/skills`.
- **Формат:** папка со файлом `SKILL.md` в корне. Наш формат (`name` и `description` в шапке, тело инструкции) совместим с этим.

**Следствие для нас.** Наш `skills/` — собственная раскладка набора, и харнесс её сам не подхватывает: в этой сессии в каталоге видны только четыре встроенных скилла. Значит, работают два пути:

1. **Ручная загрузка (основной, переносимый).** Агент читает `skills/<имя>/SKILL.md` по указанию из `AGENTS.md`. Работает в любом агенте: DSH, Claude Code, Cursor. Ничего устанавливать не нужно.
2. **Нативная подгрузка (адаптер).** Готово: `python scripts/make_skill_adapters.py` создал 42 ссылки — по четырнадцать навыков в `.dsh/skills` (источник `project-dsh` у харнесса), `.claude/skills` и `.agents/skills`. Только ссылки, без копий; проверка — `python scripts/verify_adapters.py` (десятая проверка в `verify.py`). Каталоги оболочек в публичную историю не коммитятся.

**Чего пока не подтверждено.** В сессии, где адаптеры создавались, каталог навыков не изменился: видны те же четыре встроенных. Значит, харнесс читает проектные навыки при старте сессии, а не на лету. Проверяется первым же прогоном в новой сессии: если наши четырнадцать навыков появились в каталоге — адаптер работает; если нет — остаётся ручная загрузка, и она уже прописана в `AGENTS.md`.

## 2. Как свежий агент поймёт, что делать

Цепочка без памяти о проекте:

| Шаг | Что видит агент | Откуда знает |
|---|---|---|
| 1 | человек пишет одну фразу | `README.md`, раздел «Что сделать сейчас» |
| 2 | агент читает `AGENTS.md` | правило входа, раздел 1 |
| 3 | `workspace/state.md` нет → первый запуск | `AGENTS.md`: «если state.md нет — загрузи навык 00» |
| 4 | читает `skills/00-onboarding-interview/SKILL.md` | инструкция навыка: шаг 0 (данные и источники), затем пять вопросов |
| 5 | каждый следующий шаг выбирает роутер | `skills/m2-work-router/SKILL.md`, когда состояние уже есть |

Обе точки — «первый запуск» и «как загружается навык» — прописаны в `AGENTS.md`, раздел 1. Без них свежая сессия угадывала бы.

## 3. Где прогонять: три варианта

| Вариант | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. Копия репозитория (рекомендую)** | скопировать публичную часть в отдельную папку, открыть её как корень проекта в новой сессии | имитирует настоящего пользователя: чистый клон, нет `internal/`, нет памяти сессии; данные прогона не смешиваются с проектом | нужно один раз собрать копию; правки навыков потом переносить назад |
| B. Субпапка внутри репозитория | `runs/self-01/` как песочница | рядом, просто | агент видит `internal/` и знает проект: тест перестаёт быть честным |
| C. Текущая `workspace/` | прямо здесь | ноль подготовки | я знаю метод и историю: это не тест, а демонстрация |

**Выбран A.** Копия собирается только из публичного слоя: `README.md`, `AGENTS.md`, `METHODOLOGY.md`, `GLOSSARY.md`, `LICENSE`, `skills/`, `templates/`, `knowledge/`, `scripts/`, пустой `workspace/` с описанием. Внутренняя папка не копируется — так прогон проверяет ровно то, что получит человек.

Команды для копии (Windows):

```powershell
$src = 'D:\github\ai_tech'
$run = 'D:\ai_tech-run-01'
New-Item -ItemType Directory -Path $run -Force | Out-Null
Copy-Item "$src\README.md","$src\AGENTS.md","$src\METHODOLOGY.md","$src\GLOSSARY.md","$src\LICENSE" $run
Copy-Item "$src\skills","$src\templates","$src\knowledge","$src\scripts" $run -Recurse
New-Item -ItemType Directory -Path "$run\workspace" -Force | Out-Null
Copy-Item "$src\workspace\README.md" "$run\workspace\README.md"
```

Нативная подгрузка навыков (по желанию, только ссылки):

```powershell
New-Item -ItemType Directory -Path "$run\.dsh\skills" -Force | Out-Null
Get-ChildItem "$run\skills" -Directory | ForEach-Object {
  New-Item -ItemType Junction -Path "$run\.dsh\skills\$($_.Name)" -Target $_.FullName | Out-Null
}
```

## 4. Что делает человек в прогоне

1. Открывает папку прогона как проект в **новой сессии** (без истории этого чата).
2. Пишет одну фразу: «Прочитай README.md и AGENTS.md, запусти навык 00-onboarding-interview».
3. Дальше отвечает на вопросы и **ведёт журнал прогона** по форме `templates/run-log.md`.
4. После каждой сессии — 10 минут на записи: где агент переспросил, где додумал, где пришлось объяснять.

## 5. Что считается результатом прогона

- Пройдено до артефакта; артефакт показан живому человеку в течение семи дней.
- Записан результат: обязательство, отказ с причиной или «доказательств нет».
- Журнал прогона заполнен, дефектов протокола не меньше трёх, каждый со ссылкой на файл и строку навыка.
- Проверка целостности прогона: `python scripts/verify.py` в папке прогона (должна проходить: скрипты копируются вместе с набором).

## 5a. Первый дефект нашёлся ещё до прогона

Собирая бланковый прогон, прогнал приёмку в папке без `internal/` — так выглядит репозиторий у пользователя. `verify.py` вернул **код 2**: пять проверок (заметки по источникам, внешнее исследование, структура запросов, состояние запросов, ссылки в заметках) падали на отсутствующей папке проекта. По нашим же правилам код 2 означает «работать нельзя», то есть каждый новый пользователь видел бы красную приёмку на чистом клоне.

Починено 20.10.2026: все пять проверок теперь различают «режим пользователя» (папки `internal/` нет — проверять нечего, код 0 с явным сообщением) и «сломанный проект» (папка есть, но содержимое не то — код 1 или 2). Приёмка в бланковом прогоне проходит: код 0, десять проверок.

Это ровно тот класс находок, для которого прогон и заводится: ошибка не в методике, а в том, что методику нельзя было запустить.

## 6. Что даст прогон технически
- Проверку точки входа: действительно ли свежая сессия без контекста находит `00-onboarding-interview` по одному указанию.
- Проверку загрузки навыков: работает ли ручной путь в чистом виде и нужен ли адаптер.
- Проверку форм: хватает ли 23 шаблонов, не приходится ли создавать файл, которого нет.
- Проверку проверок: проходит ли `verify.py` на данных живого прогона, а не на пустой песочнице.

## 7. Чего не делать

- Не прогонять в том же чате, где шла разработка: агент знает метод наперёд.
- Не делать копий навыков в `.dsh/skills`: только ссылки.
- Не править навыки во время прогона: сначала запись в журнал находок, правка после.
- Не считать «получилось» результатом: результат — обязательство живого человека.
