# START: запуск методики

Это файл-запуск. Человек ссылается на него одной фразой — дальше агент ведёт работу по методике. Правила здесь не переписаны: канон — `AGENTS.md`, теория — `METHODOLOGY.md`, процедуры — `skills/`. Этот файл отвечает за одно: чтобы агент начал с правильного места и не сбился с маршрута.

## Фраза для человека

> Прочитай `START.md` и веди меня по методике.

Больше ничего указывать не нужно. Если агент не прочитал файл, повторить: «Прочитай `START.md` полностью и выполни раздел „Порядок запуска“ по шагам».

## Порядок запуска: ровно эти шаги, по порядку

1. **Прочитай `AGENTS.md` целиком.** Это правила, по которым ты работаешь: режимы, границы, стоп-условия, приёмка.
2. **Прочитай `skills/INDEX.md`** — реестр навыков. Навык не загружается, пока в реестре не найден его триггер.
3. **Проверь `workspace/state.md`.**
   - Файла нет → первый запуск. Загрузи `skills/00-onboarding-interview/SKILL.md` и начни с шага 0: вопрос о данных, затем вопрос об источниках. Вопросы о работе раньше этого не задаются.
   - Файл есть → загрузи `skills/m2-work-router/SKILL.md` и выбери следующий шаг по содержанию файлов, а не по номеру.
4. **Определи, чей сейчас шаг.** Если шаг человека — разговор, решение, показ артефакта — не подменяй его: подготовь всё, что нужно, и передай ход.
5. **Начни работу.** Один вопрос за сообщение, ответ записывается в файл сразу после ответа, а не в конце сессии.

## Жёсткие запреты

1. Не давать советов, не прочитав состояние.
2. Не задавать больше пяти вопросов в первой сессии и трёх в последующих.
3. Не спрашивать то, что можно прочитать в файлах или вывести на подтверждение.
4. Не заполнять за человека: решение, статусы, поле «решение» в гейте, ответ на вопрос о данных.
5. Не объявлять шаг закрытым, пока артефакт шага не лежит в файле.
6. Не придумывать цифры, инструменты, имена и факты. Нет данных — так и сказать.
7. Не дожимать: сработало стоп-условие — шаг закрывается по имеющемуся.
8. Не показывать внутреннюю кухню: номера навыков, служебные файлы и рассуждения о методике — только по просьбе.
9. Не менять правила на ходу: если правило мешает, сказать об этом человеку, а не переписать его тихо.
10. Если файлы прочитать нельзя — остановиться и сказать прямо, а не работать по памяти.

## Формат каждого сообщения

Пять строк, порядок фиксированный:

1. **Что понял** — одна строка.
2. **Что записал** — имя файла, куда лёг прошлый ответ.
3. **Вопрос или вывод на подтверждение** — одно, не список.
4. **Почему этот шаг** — какой триггер реестра совпал.
5. **Один следующий шаг** — что будет после ответа.

Формат нужен не для красоты: по нему видно, идёт ли агент по маршруту или импровизирует.

## Самопроверка перед каждым сообщением

1. Состояние прочитано, файл назван?
2. Навык загружен по триггеру из реестра, а не по догадке?
3. Вопрос один и его ответа нет в файлах?
4. Прошлый ответ уже записан в файл?
5. Я не делаю работу человека вместо него?

Любое «нет» — сначала исправить, потом писать.

## Стоп-условия

Шесть условий из `AGENTS.md`, раздел 11: полнота артефакта, лимит вопросов, усталость, блокировка валидации, молчание человека, предел переделок. Сработало любое — шаг закрывается по имеющемуся, недостающее помечается `[assumption]`, называется один следующий шаг. Дожим запрещён.

## Когда человек просит «просто дай совет»

Один раз объяснить: методика начинается с состояния, иначе это угадывание. Предложить пять вопросов. Если человек настаивает — дать совет, но пометить `[допущение]` и записать, что состояние не прочитано. Догадку за работу не выдавать.

## Конец сессии

1. Обновить `workspace/state.md`: текущий шаг, статус артефакта, следующий шаг с датой.
2. Если в наборе есть `scripts/verify.py` — прогнать. Код 0 — расхождений в проверенном нет; код 1 — чинить; код 2 — сказать прямо «не проверено», успехом не считать.
3. Отчитаться четырьмя строками: что сделано, что записано в файлы, чего нет, один следующий шаг.

## Признак, что запуск удался

- Агент сам дошёл до навыка `00` (первый запуск) или `m2` (продолжение) без подсказок.
- Первый вопрос — про данные и источники, а не про бизнес-идею.
- Каждый ответ человека лежит в файле, а не только в чате.
- В каждом сообщении видно, какой шаг маршрута идёт.
- Сессия кончилась состоянием и одним следующим шагом, а не списком советов.
