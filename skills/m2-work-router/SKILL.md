# Мета-навык: выбор следующего действия

## Когда запускать

- Начало новой сессии или возврат после паузы.
- В состоянии противоречие: два шага выглядят начатыми.
- После провала: гипотеза не подтвердилась, артефакт не открыл дверь.
- Человек спрашивает «что делать дальше» — но не знает, на каком он шаге.

## Входы

- `workspace/state.md` — текущий шаг, статус артефакта, открытые вопросы.
- `workspace/profile.md` — есть ли профиль и узкое место.
- `workspace/hadi-tracker.md` — есть ли гипотеза с критерием.
- `workspace/assumptions.md` — статусы допущений: подтверждено, ослаблено, убито.
- Таблица артефактов: черновик / показан / обязательство.

## Главное правило

**Существующий файл не доказывает, что этап закрыт.** Критерий закрытия — содержание: заполненные поля, цитаты с метками, дата следующего шага. Пустой шаблон в нужной папке — это не пройденный шаг.

**Решение судьи читается из `workspace/state.md`**, а не из наличия файла отчёта: отчёт без вписанного решения показом не считается.

## Ветки

Ветки проверяются **сверху вниз по ярусам**: срабатывает первая подходящая, остальные не рассматриваются. Внутри три яруса: сначала незакрытые нарушения (показ запрещён), потом текущий шаг маршрута, потом после неудачи. Наличие файла не доказывает, что этап закрыт — смотрится содержание. Контур (внешний или внутренний) берётся из `workspace/state.md`.

| Ярус | Признак в состоянии | Следующее действие |
|---|---|---|
| Нарушение | «Готов к показу: да», но отчёта судьи нет | `m3-judge`, показ не начинается |
| Нарушение | Отчёт судьи есть, решение судьи «не показывать» | назад к автору: правки и новый отчёт судьи |
| Нарушение | Отчёт судьи есть, но в состоянии решения нет | показ запрещён: вписать решение из отчёта в `workspace/state.md`; наличие файла решением не считается |
| Нарушение | Гипотеза с критерием, отчёта предвалидации нет (внешний контур) | `03-prevalidation` |
| Нарушение | Ворота «заблокировано»: запрос не исполнен, сервиса нет | два выхода: человек исполняет запрос и идёт повтор `03`, либо по его решению контур переводится во внутренний; сам шаг не закрывается |
| Нарушение | Ворота вернули «не прошло», «заблокировано» или «не запускалось» | шаг не закрыт: задание в очередь, повтор `03`; в `04` не идти |
| Нарушение | Задача про документы, перед выбором средства | `m1-repo-search` |
| Нарушение | В журнале находок «предложено» без доказательства внедрения | `09-audit`: закрыть или отклонить с доказательством; показ не начинается |
| Нарушение | Контур не задан | внешний по умолчанию; спросить человека и записать его ответ — агент не выбирает |
| Шаг | Нужен документ человеку или внешнему получателю | `08-documents` |
| Шаг | Профиля нет | `00-onboarding-interview` |
| Шаг | Данных о рутине нет, человек затрудняется | `00b-telemetry-setup`, затем назад к профилю |
| Шаг | Профиль есть, поля нет | `01-field-filter` |
| Шаг | Поле есть, гипотезы с критерием нет | `02-hadi-hypothesis` |
| Шаг | Предвалидация пройдена, артефакта нет | `04-mvp-artifact` |
| Шаг | Артефакт есть, разговора нет | `06-access`, затем `07-conversation` |
| Шаг | Разговор был, вывода нет | `05-validation-gate` |
| Шаг | Внутренний контур: гипотеза есть, метрик нет | приёмка в работе и `05` в режиме метрик |
| После неудачи | Артефакт показан, обязательства нет | сбой упаковки: переделать артефакт и сообщение (`04`, `06`) |
| После неудачи | Гипотеза убита допущением в поле | сбой выбора: назад к `01`, при провале поля — к `00` |
| После неудачи | Разговор без даты следующего шага | разговор не засчитан: `06`/`07` ещё раз |
| После неудачи | Есть обязательство | новый цикл: `02`, при смене поля — `01` |
| После неудачи | Рутины не осталось, всё автоматизировано | внешний контур: `06` и `07` — узкое место в доступе к людям |

Различение «сбой упаковки против сбоя продукта» — канон Бланка: если проблема в презентации и позиционировании, переделывается упаковка; если в самом предложении, возврат к выбору поля. Правило зафиксировано в конфликтах источников.

## Порядок

1. Прочитать `workspace/state.md` первым действием.
2. Сверить состояние с файлами-артефактами: что реально заполнено.
3. Выбрать ветку по таблице.
4. Назвать причину выбора одной фразой и записать в `workspace/state.md`.
5. Загрузить навык выбранного этапа. Не загружать два сразу.

## Стоп-условия

1. **Состояние противоречиво** (артефакт «показан», но разговора в записях нет) → один вопрос человеку, потом решение.
2. **Файл состояния не обновлялся больше недели** → спросить, продолжаем ли прежний шаг, а не начинать новый.
3. **Локальный режим** → ветки с внешними запросами (`03`) заменяются пометкой `[допущение]` и записью в очередь.
4. **Нет данных для выбора** → начать с `00-onboarding-interview`, а не угадывать.

## Что выдать

Один следующий шаг, причину выбора, обновлённый `workspace/state.md`.

## Чего не делать

- Не перезапускать маршрут с нуля при каждом вопросе.
- Не пропускать ворота предвалидации во внешнем контуре.
- Не выбирать шаг по признаку «интереснее».
- Не начинать новый цикл, пока текущий не закрыт или не убит.
- Не считать наличие файла доказательством завершённого шага.

Незнакомые слова — в `GLOSSARY.md`. Маршрут целиком — `METHODOLOGY.md`, раздел 6.
