# Мета-навык: выбор следующего действия

## Когда запускать

- Начало новой сессии или возврат после паузы.
- В состоянии противоречие: два шага выглядят начатыми.
- После провала: гипотеза не подтвердилась, артефакт не открыл дверь.
- Человек спрашивает «что делать дальше» — но не знает, на каком он шаге.

## Входы

Роутер читает **состояние** и сверяет его с файлами. Без признака в файле строка не срабатывает — догадываться запрещено.

- `workspace/state.md` — «Текущий шаг», «Ветка», «Нужен документ или готовое решение», «Контур», «Задано вопросов», «Номер сессии», «Переделок сделано», «Версия результата», «Решение судьи», «Решение человека», «Подписал человек», «Показ состоялся», счётчики блока «Внешняя проверка», «Прогонов метрик».
- `workspace/profile.md` — есть ли профиль и узкое место.
- `workspace/hadi-tracker.md` — есть ли гипотеза с критерием.
- `workspace/assumptions.md` — статусы допущений: подтверждено, ослаблено, убито.
- `workspace/artifact.md` и файлы в `workspace/artifacts/` — что реально собрано.
- `workspace/memory/decisions.md` — подпись человека и вердикт.
- `workspace/judge-report-<дата>.md` — отчёт судьи и его решение.
- `workspace/audit-log.md` — журнал находок: есть ли открытые.
- `workspace/research/prevalidation-<дата>.md` — отчёт ворот (не только строка пути).

## Главное правило

**Существующий файл не доказывает, что этап закрыт.** Критерий закрытия — содержание: заполненные поля, цитаты с метками, дата следующего шага. Пустой шаблон в нужной папке — это не пройденный шаг.

**Решение судьи читается из `workspace/state.md`**, а не из наличия файла отчёта: отчёт без вписанного решения показом не считается.

**`08-documents` и `m1-repo-search` — ветки, а не шаги маршрута.** Нужен документ или готовое решение — маршрут уходит в ветку, строка «Текущий шаг» не меняется, во «Ветку» пишется название и исходный шаг. По завершении ветки возвращаешься в этот шаг, а не начинаешь маршрут заново.

**Главный роутер — эта таблица.** Строка «Дальше» в `skills/INDEX.md` описывает порядок навыков, а не маршрут; при расхождении выигрывает таблица ниже (см. `skills/INDEX.md`, правило 6).

## Порядок

1. Прочитать `workspace/state.md` первым действием.
2. Проверить стоп-условия роутера (ниже) — они идут **до** таблицы.
3. Сверить состояние с файлами-артефактами: что реально заполнено.
4. Идти по таблице сверху вниз: ярус «Нарушение» → «Шаг» → «После неудачи». Срабатывает первая подходящая строка, остальные не рассматриваются.
5. Записать в `workspace/state.md`: «Причина выбора шага», «Текущий шаг», «Ветка» / «Нужен документ или готовое решение» — что изменилось.
6. Загрузить навык выбранного этапа. Не загружать два сразу.

## Стоп-условия роутера (проверяются до таблицы)

1. **Состояние противоречиво** (артефакт «показан», но показа-события в состоянии и записи разговора нет) → один вопрос человеку, потом решение.
2. **Файл состояния не обновлялся больше недели** → спросить, продолжаем ли прежний шаг, а не начинать новый.
3. **Локальный режим** (`workspace/LOCAL-ONLY`) → строки с внешними запросами (`03`) заменяются пометкой `[допущение]` и записью в очередь; шаг закрывается по имеющемуся, ворота считаются заблокированными.
4. **Нет данных для выбора** → начать с `00-onboarding-interview`, а не угадывать.

Канон шести стоп-условий — `AGENTS.md`, раздел 11; роутер уточняет только своё. Вопросы о контуре и противоречии входят в лимит.

## Ветки

| Ярус | Признак в состоянии и файлах | Следующее действие |
|---|---|---|
| Нарушение | В блоке «Внешняя проверка» счётчик выше порога: 2 раунда без прогресса, повторяющийся блокер ≥ 2, регрессия ≥ 1, открытых вопросов без источника ≥ 3 | `m4-external-check`: остановить правки, составить запрос по шаблону, отдать человеку; до ответа не править |
| Нарушение | В журнале находок «предложено» или «внедрено» без доказательства, либо «отклонено» без того, кто решил | `09-audit`: закрыть с доказательством внедрения; показ не начинается |
| Нарушение | Отчёт судьи «показывать», но «Подписал человек» в состоянии пуст и записи в `workspace/memory/decisions.md` нет | `04-mvp-artifact`, раздел «Показ и подпись»: получить решение человека и вписать цитату, канал, дату; показ не начинается |
| Нарушение | Версия в артефакте или отчёте судьи расходится с «Версией результата» в состоянии | остановиться: привести к версии из `workspace/state.md`, новый отчёт судьи |
| Нарушение | «Готов к показу: да», но отчёта судьи нет или «Решение судьи» пусто | `m3-judge`; показ не начинается |
| Нарушение | Отчёт судьи есть, решение судьи «не показывать» | назад к автору: правки и новый отчёт судьи; если «Переделок сделано» = 2 из 2 — новых правок нет, только решение человека по имеющейся версии |
| Нарушение | «Переделок сделано» = 2 из 2 | новых правок не делать: показать как есть — только с отчётом судьи «показывать» и подписью человека (`AGENTS.md`, раздел 11, пункт 6) |
| Нарушение | «Ветка» заполнена, работа ветки не закрыта | вернуться в навык ветки (`08-documents` или `m1-repo-search`) и закрыть её; маршрут не продолжается |
| Шаг | «Контур» пуст | спросить человека и записать его ответ; вопрос входит в лимит; агент не выбирает |
| Шаг | «Нужен документ или готовое решение» = документ | `08-documents`, затем вернуться в «Причина выбора шага» (исходный шаг) |
| Шаг | «Нужен документ или готовое решение» = готовое решение | `m1-repo-search`, затем вернуться в исходный шаг |
| Шаг | Профиля нет | `00-onboarding-interview` |
| Шаг | Данных о рутине нет, человек затрудняется | `00b-telemetry-setup`, затем назад к профилю |
| Шаг | Профиль есть, поля нет | `01-field-filter` |
| Шаг | Поле есть, гипотезы с критерием нет | `02-hadi-hypothesis` |
| Шаг | Гипотеза с критерием есть, отчёта предвалидации нет (внешний контур) | `03-prevalidation` |
| Шаг | Ворота «заблокировано»: запрос не исполнен, сервис недоступен | записать «не исследовано» и задание в очередь; по решению человека — внутренний контур; шаг не закрыт, в `04` не идти |
| Шаг | Ворота «не прошло» или «не запускалось» | не повторять те же ворота: `02` — переформулировать гипотезу; задание в очередь; в `04` не идти |
| Шаг | Ворота «прошло», артефакта нет | `04-mvp-artifact` |
| Шаг | Артефакт собран, отчёта судьи нет или решение пусто | `m3-judge` |
| Шаг | Внутренний контур: метрики есть, прогонов меньше трёх | `00b-telemetry-setup` (или продолжение замера), гейта нет |
| Шаг | Внутренний контур: три и больше прогонов метрик | `05-validation-gate` в режиме метрик |
| Шаг | Артефакт собран и проверен, показа не было | `06-access`, затем `07-conversation` |
| Шаг | Разговор назначен, но ещё не прошёл | `07-conversation` (подготовка и разговор); `06-access` повторно не грузится |
| Шаг | Разговор прошёл, записи нет | `07-conversation`: записать по дебрифу, потом гейт |
| Шаг | Записи есть, вывода нет | `05-validation-gate` |
| Шаг | Вердикт вынесен: в «Решении человека» «закрываем гипотезу» | новый цикл: `02-hadi-hypothesis`; если поле не выдержало — `01-field-filter` |
| Шаг | Вердикт вынесен: `RUN N` или «продолжаем» | `07-conversation`: нужны ещё разговоры, а не переделка артефакта |
| Шаг | Вердикт `BUILD` / `BUILD AS EXPERIMENT` | новый цикл: `02` — следующая гипотеза, при смене поля `01` |
| Шаг | Рутины не осталось, всё автоматизировано | внешний контур: `06-access` и `07-conversation` — узкое место в доступе к людям |
| После неудачи | Артефакт показан, обязательства нет, человек решил продолжать, «Переделок сделано» меньше 2 | сбой упаковки: переделать артефакт и сообщение (`04`), затем `06` |
| После неудачи | Гипотеза убита допущением в поле | сбой выбора: назад к `01`; при провале поля — к `00` |
| После неудачи | Разговор без даты следующего шага | разговор не засчитан: `07` ещё раз |
| После неудачи | Есть обязательство | новый цикл: `02`, при смене поля — `01` |

**Сбой упаковки и сбой поля — разные вещи.** Если проблема в презентации и позиционировании, переделывается упаковка; если в самом предложении, возврат к выбору поля. Правило зафиксировано в конфликтах источников.

## Что выдать

Один следующий шаг, причину выбора (записана в состояние), обновлённый `workspace/state.md`.

## Чего не делать

- Не перезапускать маршрут с нуля при каждом вопросе.
- Не пропускать ворота предвалидации во внешнем контуре.
- Не выбирать шаг по признаку «интереснее».
- Не начинать новый цикл, пока текущий не закрыт или не убит.
- Не считать наличие файла доказательством завершённого шага.
- Не делать новых правок после второго круга переделок.
- Не грузить `06-access`, когда разговор уже назначен: дальше идёт `07-conversation`.

Незнакомые слова — в `GLOSSARY.md`. Маршрут целиком — `METHODOLOGY.md`, раздел 6.
