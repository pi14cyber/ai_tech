# Журнал находок

## Когда запускать

- После разбора чужого репозитория, набора навыков или документа.
- После сюрприза или провала: что-то сломалось не так, как ожидали.
- Перед правкой правил, навыков и шаблонов.
- Когда приём из чужого проекта собираются перенести к нам.

## Зачем

Без журнала находки двух видов смешиваются: «прочитал в описании» и «увидел в файле». Первое звучит убедительно и часто неверно. Второе проверяемо. Журнал разводит их и не даёт объявить правку сделанной, пока она только предложена.

## Классы доказательств

| Класс | Что это | Как помечать |
|---|---|---|
| **A. Подтверждено файлом** | фраза есть в файле, указан путь и строка | `путь:строка` |
| **B. Сказал человек** | цитата из разговора или переписки; проверить дословность | «сказано, не проверено» |
| **D. Заявлено описанием** | сказано в README, витрине, обзоре; в файлах не проверял | «по описанию, не проверено» |
| **C. Вывод агента** | моя интерпретация, а не текст источника | `[допущение]` |

Класс B не становится классом A без чтения файла. Урок из наших разборов: описание репозитория не равно его содержимому — навык, отсутствующий в витрине, находился в файлах, и наоборот.

## Форма записи

| Поле | Что писать |
|---|---|
| # | номер строки |
| Дата | когда нашли |
| Что нашли | одно предложение: что именно увидели; для интервью — цитата и кто |
| Класс | A, B, C или D |
| Где (файл:строка) | конкретный файл и строка; для класса B — кто и когда сказал |
| Статус | `найдено` → `предложено` → `внедрено` / `отклонено` → `проверено` |
| Доказательство внедрения | ссылка на исправленный файл и строку; без неё «внедрено» не ставится |
| Кто решил | человек, принявший решение по находке; обязательно для «отклонено» |
| Кто проверил | человек или отдельный проход; для «проверено» обязательно |

**Чтение журнала.** Журнал читается перед показом результата и перед правкой правил: находка в статусе «предложено» без доказательства внедрения — открытая, и решение по ней принимает человек.

## Как закрыть находку

Находка закрывается только доказательством: статус `внедрено` — ссылка на исправленный файл и строку; `отклонено` — причина и кто решил; `проверено` — кто проверил. Открытая находка («найдено», «предложено») не блокирует работу навсегда: в маршруте есть ветка закрытия. Показ результата с открытой находкой запрещён до её закрытия или явного решения человека.

## Правило, ради которого журнал существует

**Предложенная правка не равна исправленному.** Запись получает статус `внедрено` только когда файл изменён, и `проверено` только когда изменение прошло проверку. Пока правило живёт в журнале, оно не действует.

Второе правило: **не тихо переписывать**. Если находка противоречит тому, что уже написано, сначала фиксируется противоречие и его причина, потом правится текст. Молчаливая замена запрещена.

## Куда писать

Журнал — `workspace/audit-log.md` по шаблону `templates/audit-log.md`. Форма обязательна: без неё «предложил и забыл» не отличить от «внедрено».

- Проект: рабочая папка решений и заметок проекта.
- Пользователь: `workspace/audit-log.md` — что нашли, какого класса, где и внедрено ли. Решения живут в `workspace/memory/decisions.md`, находки — в журнале находок; это разные файлы.
- Внешний факт, который пригодится и другим, — в базу знаний по правилам карточки, а не только в журнал.

## Стоп-условия

Канон — шесть условий в `AGENTS.md`, раздел 11 (навык только уточняет своё).

1. **Находка без ссылки** → не запись, а белое пятно: писать «не проверено» и где искали.
2. **Предложение без проверки** → статус `предложено`, не `внедрено`.
3. **Противоречие с текущим текстом** → сначала запись о противоречии, потом правка.
4. **Находка про чужие персональные данные** → в журнал не попадает: обезличить или не писать.

## Чего не делать

- Не пересказывать чужой репозиторий целиком: только то, что переносится.
- Не переносить чужие файлы и код: берём приёмы и ссылки.
- Не писать «исправлено» по факту плана.
- Не терять источник: запись без адреса бесполезна через месяц.
- Не выдавать класс B за класс A.

Незнакомые слова — в `GLOSSARY.md`. Правило «судья не автор» — `AGENTS.md`, раздел 5; отдельный проход проверки — `m3-judge`.
