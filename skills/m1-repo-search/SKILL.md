# Мета-навык: поиск решения под задачу

## Где он в нашем устройстве

Навыки делятся на два уровня:

- **навыки этапа** — процедура одного шага маршрута: онбординг, поле, гипотеза, предвалидация, артефакт, валидация;
- **мета-навыки** — умения, которые применяются на любом шаге: найти готовое решение, выбрать следующий шаг по состоянию, проверить результат отдельным проходом.

Этот навык — первый мета-навык. Он не привязан к шагу: к нему обращаются, когда у человека есть конкретная задача и надо понять, не построено ли уже решение.

## Когда запускать

- У человека конкретная операция, для которой может существовать готовое решение: разобрать PDF, собрать таблицу, сделать локальный поиск по архиву, автоматизировать браузер.
- Перед сборкой своего: правило часа — может, час машины уже потрачен кем-то другим.
- После предвалидации: факты собраны, нужен инструмент под них.

## Отличие от «списка инструментов»

Ищем **под задачу**, а не «полезные ИИ-сервисы». Критерий один: закрывает ли это операцию из шага 1. Инструмент, который не закрывает, в список не попадает, даже если он популярный.

## Порядок работы

### Шаг 1. Сформулировать задачу операционно

```
[вход: что есть на руках]
→ [операция: что надо сделать]
→ [выход: что должно получиться]
+ ограничения: локально или облако, бюджет, язык, объём, лицензия
```

Пример: «сканы договоров в PDF → вытащить таблицы → CSV, локально, до ста файлов, бесплатно». Без такой формулировки поиск превращается в листание каталогов.

### Шаг 2. Собрать ключи поиска

- по операции, по-английски покрытие шире: `pdf to markdown`, `table extraction`, `local rag`, `browser automation`;
- по форме решения: `CLI`, `python library`, `MCP server`, `docker compose`;
- по каналам: поиск по репозиториям, тематические списки (`awesome-*`), каталоги серверов MCP, документация инструментов, которые уже используются.
- Каждая находка фиксируется с адресом и датой: **нет ссылки — нет находки.**

### Шаг 3. Триаж: короткий список из 3–7 кандидатов

По каждому: назначение одной строкой, лицензия, дата последнего коммита, размер, стек, требует ли облака, есть ли тесты.

Сразу отсекать:

- архивные и заброшенные;
- без лицензии или с лицензией, несовместимой с нашим распространением;
- требующие обязательного облака, если задача сформулирована «локально»;
- обёртки без исходников и без спецификации;
- решения, которые в описании обещают всё сразу.

### Шаг 4. Проверка чтением, а не витриной

1. Клонировать поверхностно в отдельную песочницу, записать коммит и дату.
2. Прочитать README, документацию, ключевые файлы, тесты.
3. Проверить по файлам 2–3 заявления из описания. Урок из разбора чужих наборов: витрина не равна содержимому.
4. Отметить, что не проверено, прямо.

Уровень находки — `[внешнее]`: это факты для планирования, а не доказательство, что решение подходит человеку.

### Шаг 5. Решение и запись

Одно из трёх:

| Решение | Когда |
|---|---|
| **Взять как зависимость** | лицензия совместима, решение закрывает операцию, стоимость поддержки понятна |
| **Взять как приём** | чужой код не нужен, достаточно перенять форму и переписать своими словами со ссылкой |
| **Отклонить** | не закрывает операцию, несовместимая лицензия, требует инфраструктуры, которой у человека нет |

Запись решения обязательна: что нашли, ссылка, дата, коммит, что взяли, что отклонили и почему.

## Куда писать

Форма — `templates/research-repos.md`, копия в `workspace/research/repos.md`.

- Список найденного и решение — `workspace/research/repos.md`.
- Разбор выбранного — `workspace/research/<тема>.md`: наблюдения со ссылками на файлы и номера строк.
- Решение — `workspace/memory/decisions.md` или журнал решений проекта.
- Факт, который пригодится и другим, — в базу знаний по правилам карточек.

## Стоп-условия

1. **Три кандидата закрывают задачу** → триаж и выбор. Дальше искать «идеальное» запрещено: это уже коллекционирование.
2. **Двадцать минут поиска без кандидата** → задача сформулирована слишком общо, либо решения нет: записать в белые пятна и вернуться к формулировке.
3. **Локальный режим** → клонирование и внешние запросы запрещены: список без проверки, пометка «не проверено».
4. **Лицензия несовместима** → отклонить и записать причину, не переносить код.

## Чего не делать

- Не искать «лучший инструмент вообще»: без операции это каталог.
- Не верить звёздам, описаниям и скриншотам без чтения файлов.
- Не тащить зависимость ради одной операции, если хватает скрипта или команды.
- Не показывать человеку список из тридцати ссылок: три-пять с причиной и одним решением.
- Не публиковать чужие репозитории и код в нашем наборе: берём приёмы и ссылки, а не файлы.
- Не путать находку с валидацией: инструмент не доказывает, что задача человека реальна.

Незнакомые слова — в `GLOSSARY.md`. Правила уровней доказательности — `AGENTS.md`, раздел 3.
