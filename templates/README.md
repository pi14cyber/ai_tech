# Шаблоны

Пустые формы, которые заполняются в `workspace/`. Агент **никогда не пишет в `templates/`**: он копирует нужный шаблон в `workspace/` и заполняет копию.

**Сколько их:** 28 шаблонов (без этого README). Число и таблицу сверяет машинно `scripts/verify_consistency.py`.

## Разметка полей по заполняющему

Приём, которого нет у разобранных нами чужих наборов: **у каждого шаблона назван владелец полей** — это снимает главный вопрос человека «а что мне тут писать».

- `[человек]` — знает только он: личный опыт, доступы, границы, выбор, решения.
- `[агент]` — выводится из базы и уже сказанного.
- `[внешний]` — приносит внешний исследователь со ссылкой и датой.
- `[замер]` — приходит из данных замера (нулевой цикл).

Метка по умолчанию — колонка «Кто заполняет» в таблице выше. Если у поля другой владелец, он помечается прямо в шаблоне: например, главные решения в `decisions.md` и `state.md` помечены как человеческие.

## Правила заполнения

1. Копия, а не оригинал. Правки только в `workspace/`.
2. Метка достоверности обязательна у каждого пункта: `[validated: data]`, `[validated]`, `[assumption]`.
3. Статусы меняет человек. Агент может предложить смену и привести основание.
4. Пустое поле лучше выдуманного: пустое видно, выдуманное нет.
5. Новый шаблон добавляется в таблицу этого файла и в проверку числа шаблонов — иначе он невидим.

## Пара «запрос — ответ»

Заготовка ответа копируется под конкретный запрос **вместе с ним**; пар две — у человека и у проекта (канон — `AGENTS.md`, раздел 4):

- у человека: `templates/request-short.md`/`request-full.md` → `workspace/requests/<id>.md`; `templates/response-short.md`/`response-full.md` → `workspace/responses/<id>.answer.md`;
- у проекта: та же пара в его внутренней папке запросов и ответов (пути — `AGENTS.md`, раздел 4).

Полный порядок (триггер → отправка → разбор → архив) — один канон: `skills/m4-external-check`, раздел «Полный пайплайн запроса».
