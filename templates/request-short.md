# ШАБЛОН: короткий запрос

> **Как пользоваться.** Копировать этот файл, заполнить поля и вопросы. Ничего не удалять: скелет и порядок разделов обязательны, иначе запросы перестают быть сравнимыми и проверка структуры их бракует. Вопросов — от трёх до пяти, канал один, ожидаемый ответ до 1200 слов.

**Идентификатор:** `req_XX_short`
**Дата:** ГГГГ-ММ-ДД
**Каналы:** один, на выбор по покрытию темы
**Категория:** `быстрая` — короткий объём, один канал, запускать в режиме быстрого поиска
**Ответ писать в:** `workspace/responses/req_XX_short.answer.md`
**Вопросов:** 0 (предел — шесть)
**Состояние:** заполняется автоматически: `python scripts/verify_state.py --write`

> **Инструкция для исследователя.** Это запрос на сбор нейтральной эмпирической фактуры. У заказчика нет предпочтительного ответа. Оптимистичные прогнозы и утверждения без ссылки будут забракованы. Если данных нет — так и написать, это результат.

## 3. Контракт формата

1. **Нет ссылки — нет факта.** Каждое утверждение, цифра и ограничение — с прямой ссылкой и датой обращения.
2. **Запрет прогнозов.** Только свершившиеся факты и действующие условия.
3. **Микро-факты вместо обобщений:** версия, формат, строка лицензии, страница документации, запись в трекере.
4. **Пропущенный идентификатор считается неотвеченным.**
5. Последняя строка ответа: «Чего найти не удалось: …».

## 4. Структура ответа

```markdown
### Q1.1. Название вопроса

- **Факты за:**
- **Факты против:**
- **Белые пятна:**
```

В конце ответа — таблица покрытия: идентификатор, статус (отвечено / белое пятно), число источников.

## 5. Белые пятна

Белым пятном считается только то, что искали задокументированно: каналы, формулировки, проверенные реестры, дата. «Не нашлось» без описания поиска белым пятном не считается.

## 6. Параллельные каналы

Короткий запрос уходит в один канал. Если он не убил гипотезу и цена следующего шага высока — берётся полный запрос по шаблону `templates/request-full.md`.
