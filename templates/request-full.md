## 3. Контракт формата

1. **Нет ссылки — нет факта.** Каждое утверждение, версия, тариф и ограничение — с прямой ссылкой и датой обращения.
2. **Запрет прогнозов.** Только свершившиеся факты, действующие версии и текущие условия.
3. **Микро-факты вместо обобщений:** версия продукта, формат файла, строка лицензии, страница документации, запись в трекере задач.
4. **Пропущенный идентификатор считается неотвеченным.**
5. Последняя строка ответа: «Чего найти не удалось: …».
6. **Без кода.** Ответ — источники и алгоритмы словами: ссылка, название, шаги, критерии применимости, ограничения. Код, псевдокод, готовые скрипты и «пример реализации» не нужны и не принимаются; если источник сам содержит код, нужна ссылка и описание словами, а не копия.

## 4. Структура ответа

```markdown
### Q1.1. Название вопроса

- **Источники (ссылка + дата):**
- **Что говорит источник:**
- **Алгоритм словами:**
- **Критерии применимости / ограничения:**
- **Белые пятна:**
```

В конце ответа — таблица покрытия: идентификатор, статус (отвечено / белое пятно), число источников.

## 5. Белые пятна

Белым пятном считается только то, что искали задокументированно: каналы, формулировки, проверенные реестры, дата. Совпадение белых пятен в двух независимых каналах — практическое подтверждение, что данных в открытом доступе нет. «Не нашлось» без описания поиска белым пятном не считается.

## 6. Параллельные каналы

Один и тот же файл уходит минимум в два независимых канала. Полнота ответа проверяется по каждому каналу отдельно, факты сводятся по идентификаторам.
