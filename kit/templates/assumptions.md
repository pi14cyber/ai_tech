# Допущения и условия смерти

**Проверка:** машинной проверки нет: статус допущения меняется только по данным, гейт `kit/skills/05-validation-gate` читает файл.

Правило, взятое из `sreshtalluri/mom-test` (`kit/templates/assumptions.md`:5-6): **у каждого допущения обязательна колонка «условие смерти»** — что именно должно случиться, чтобы допущение считалось мёртвым. Без условия смерти допущение проверять нельзя, потому что любой результат можно будет объявить подтверждением.

## Таблица

Номер допущения — `A1` для первой строки, `A2` для второй и так далее: в интервью и гейте ссылка идёт по номеру `A<N>`, а не по номеру `#`.

| № (A1, A2…) | Допущение | Почему верим сейчас | Условие смерти | Статус | Кем подтверждено |
|---|---|---|---|---|---|
| A1 | | | | UNTESTED | |

**Статусы:** `UNTESTED` — не проверяли; `WEAKENED` — данные против; `SUPPORTED` — есть подтверждающие сигналы ступени 8+; `KILLED` — условие смерти сработало.

## Порядок

1. **Самое рискованное допущение — первой строкой.** Рискованное значит: если оно мёртвое, весь план теряет смысл.
2. **Оно же становится «страшным вопросом»** и задаётся в первые пять минут разговора, пока собеседник не начал вежливничать.
3. **Условие смерти формулируется до разговора**, а не после. Формулировка проверяемая: не «людям не понравится», а «из десяти разговоров меньше трёх подтвердят, что проблема повторяется еженедельно».
4. **Статус меняется только по данным.** Мнение владельца статус не меняет.

## Связь с гейтом

Гейт доказательств (`kit/skills/05-validation-gate`) считает вердикт по допущению с наименьшим числом подтверждающих интервью. Если допущение получило статус `KILLED`, а запрос работает только при его истинности, вердикт будет «сначала три разговора».

## Где хранится

Копия шаблона в `workspace/assumptions.md`. Статусы меняет человек, агент только предлагает.
