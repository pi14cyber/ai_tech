# Структура репозитория

Карта файлов: что где лежит и зачем. **Правило:** публичные файлы и папки перечислены здесь; новая сущность без строки в этой карте невидима — проверка `kit/scripts/verify_structure.py` вернёт код 1.

**Одна машинная папка.** Всё, что нужно только агенту, лежит в `kit/`. В корне — только вход для человека и его зоны.

## Корень — для человека

| Файл или папка | Назначение |
|---|---|
| `README.md` | вход для человека: один экран, что это, как начать, куда кидать файлы |
| `inbox/` | входящие файлы человека: выгрузки, документы, ответы сервисов (в публичную историю не коммитятся) |
| `workspace/` | рабочие файлы человека: профиль, состояние, артефакты, решения (не публикуются) |
| `LICENSE` | лицензия набора |
| `runs/` | песочницы прогонов, в т.ч. `runs/self-01` для приёмки (в публичную историю не коммитятся) |
| `gtm-cofounder/` | подмодуль: чужой проект-образец, свои правила (`.gitmodules`); наш набор им не управляется |

## `kit/` — вся машинная часть

| Файл | Назначение |
|---|---|
| `kit/START.md` | запуск: порядок шагов, запреты, формат ответа и стандарт первого ответа |
| `kit/AGENTS.md` | канон правил агента: режимы, доказательства, сеть, зоны, стоп-условия, приёмка |
| `kit/METHODOLOGY.md` | теория метода целиком: принципы, маршрут, гейт, границы |
| `kit/GLOSSARY.md` | словарь: наши слова в обычной речи значат другое |
| `kit/STRUCTURE.md` | эта карта: структура файлов и правила её поддержки |
| `kit/CHANGELOG.md` | история версий; версия ставится тегом на коммит |

## `kit/rules/` — канон чисел и статусов

| Файл | Назначение |
|---|---|
| `kit/rules/canon.json` | единственный источник чисел, лимитов, статусов, словарей и запрещённых формулировок |
| `kit/rules/check_hashes.json` | манифест sha256 проверок: подмена тела проверки видна, обновляется `python kit/scripts/verify_canon.py --write-hashes` |

Менять числа и статусы можно только здесь; остальные файлы сверяются с каноном (`verify_canon.py`).

| `04-mvp-artifact` | артефакт-предлог и сообщение |
| `05-validation-gate` | гейт: счёт сигналов и вердикт |
| `06-access` | доступ к людям: сеть, канал, список |
| `07-conversation` | разговор и разметка сигналов |
| `08-documents` | документы: сверка, судья, показ |
| `09-audit` | журнал находок и проверка проверок |

Реестр с триггерами — `kit/skills/INDEX.md`. Навык читается целиком, канон стоп-условий — в `kit/AGENTS.md` §11 (навыки не переписывают его, только уточняют).

## `kit/templates/` — пустые формы

Копируются в `workspace/` (или во внутреннюю папку проекта) и заполняются там; агент не правит `kit/templates/`. Полный список форм и кто их заполняет — `kit/templates/README.md`.

| Группа | Файлы |
|---|---|
| Состояние и шаги | `state.md`, `profile.md`, `activity-map.md`, `field-choice.md`, `assumptions.md`, `hadi-tracker.md` |
| Проверка и артефакт | `prevalidation-report.md`, `artifact.md`, `judge-report.md`, `interview.md`, `decisions.md` |
| Люди и доступ | `people.md`, `access-log.md`, `network.md` |
| Запросы и ответы | `request-short.md`, `request-full.md`, `response-short.md`, `response-full.md`, `research-response.md`, `research-queue.md`, `research-repos.md` |
| Журналы | `audit-log.md`, `run-log.md`, `time-log.md`, `file-log.md`, `tracker-export.md`, `source-conflicts.md` |
| Знания | `knowledge-card.md` |
| Описание | `kit/templates/README.md` |

## `kit/scripts/` — машинные проверки и обслуживание

| Скрипт | Назначение |
|---|---|
| `kit/scripts/verify.py` | одна команда приёмки: запускает все проверки ниже |
| `kit/scripts/verify_canon.py` | сверка публичных файлов с `kit/rules/canon.json` |
| `kit/scripts/check_workspace.py` | проверка артефактов человека: ворота, судья, артефакт, журнал, решения, состояние |
| `kit/scripts/verify_sandbox.py` | копия публичного слоя в `runs/self-01` совпадает с репозиторием |
| `kit/scripts/verify_structure.py` | все публичные файлы описаны в `kit/STRUCTURE.md` и карта не врёт |
| `kit/scripts/verify_harness.py` | заметки по источникам и целостность деклараций |
| `kit/scripts/verify_knowledge.py` | паспорт и срок годности карточек, сверка с индексом |
| `kit/scripts/verify_research.py` | полнота ответов внешнего исследователя |
| `kit/scripts/verify_requests.py` | структура запросов и правило архивации закрытых |
| `kit/scripts/verify_state.py` | состояние и архив запросов сходятся с диском |
| `kit/scripts/verify_skills.py` | шапки навыков и имена |
| `kit/scripts/verify_docs.py` | названные в публичных файлах пути существуют |
| `kit/scripts/verify_layers.py` | публичный слой не ссылается на внутренний |
| `kit/scripts/verify_notes.py` | ссылки в заметках о клонах |
| `kit/scripts/verify_adapters.py` | адаптеры оболочек — только ссылки, без копий |
| `kit/scripts/verify_consistency.py` | числа, таблицы, блоки состояния |
| `kit/scripts/archive_requests.py` | перенос закрытых запросов и ответов в архив |
| `kit/scripts/sync_sandbox.py` | пересборка `runs/self-01` после правок публичного слоя |
| `kit/scripts/make_skill_adapters.py` | ссылки навыков в каталоги оболочек |
| `kit/scripts/make_answer_blanks.py` | заготовки ответов под существующие запросы |

## Рабочие зоны

| Зона | Назначение |
|---|---|
| `workspace/` | данные человека: профиль, артефакты, запросы, решения (не публикуется) |
| `inbox/` | входящие файлы человека: документы, выгрузки, ответы сервисов (не публикуется) |
| `kit/internal/` | материалы проекта-кейса: черновики, отчёты аудитов, архивы запросов |
| `runs/` | песочницы прогонов, в т.ч. `runs/self-01` для приёмки |
| `.dsh/`, `.claude/`, `.agents/` | адаптеры оболочек: только ссылки на `kit/skills/` |
| `gtm-cofounder/` | подмодуль: чужой проект-образец, свои правила (`.gitmodules`); наш набор им не управляется |

Внутренний слой (`kit/internal/`, не входит в набор пользователя):

| Подпапка | Назначение |
|---|---|
| `kit/internal/draft/` | черновики метода и презентации, отчёты аудитов, заказы на исправление |
| `kit/internal/docs/` | книги и первоисточники, выжимки |
| `kit/internal/research/` | клоны чужих репозиториев для разбора (gitignored) |

`workspace/`, `kit/internal/research/`, `runs/`, каталоги оболочек в публичную историю не коммитятся (`.gitignore`).

## Поддержка структуры

1. Новый файл в корне, навык, шаблон или скрипт → строка в этой карте.
2. Удалил файл → удали строку; проверка ловит и пропажу, и устаревшую запись.
3. Числа и статусы — только в `kit/rules/canon.json`; структура — только здесь.
4. Проверка: `python kit/scripts/verify_structure.py` (входит в `python kit/scripts/verify.py`).
