# Устройство набора: предложение и разбор

**Откуда:** владелец передал 18.10.2026 предложение по устройству репозитория и ролям (внешний документ, уровень `[внешнее]`).

**Решение владельца:** собирать репозиторий как агентский стартер-кит по образцу `gtm-cofounder`, строго отделив публичный инструмент от папки со стримом.

---

## 1. Что в предложении совпало с уже сделанным

| Утверждение предложения | Где это уже есть |
|---|---|
| Ролей шесть, а не три | `07_assistant_method.md`, часть 11: владелец, скептик, исследователь, исполнитель, судья, рынок |
| Проверка фактов через внешний ИИ отделена от проверки спроса через людей | части 14 и 15: цепочка из четырёх звеньев и предвалидация |
| Фильтр непроверяемости как личный ров | `03_pipeline.md`, часть B, шаг 0 |
| МВП нужен как пропуск к эксперту, а не как проверка спроса | `07_assistant_method.md`, часть 5 |
| В HADI блок Data заменяется обязательствами | `03_pipeline.md`, часть J |
| Формула гипотезы и спринт 1–2 недели сохраняются | `internal/docs/hadi.md` |

То есть архитектура в черновиках уже была, и разбор это подтвердил, а не изменил.

## 2. Что принимаю

1. **Три зоны репозитория:** публичный инструмент, шаблоны, внутренняя папка стрима.
2. **`workspace/` как песочница:** единственное место, куда агент пишет данные конкретного человека.
3. **`templates/` только на чтение** для агента, заполненные копии уходят в `workspace/`.
4. **`METHODOLOGY.md` как чистая теория** в корне: методика плюс пайплайн, без внутренней кухни.
5. **`internal/` как живой кейс:** папка остаётся в репозитории и показывает, как этой же системой собран стрим.
6. **Набор навыков 00–05**, повторяющий шаги пайплайна.

## 3. Что корректирую

**Папка сама по себе не делает шаблоны неизменяемыми.** Разделение `templates/` и `workspace/` технически не запрещает запись: запрет должен быть правилом в `AGENTS.md` плюс, при желании, проверкой перед коммитом. Поэтому правило пишу в `AGENTS.md`, а не полагаюсь на структуру.

**`workspace/` не должен попадать в публичную историю.** Иначе чужие данные утекут в открытый репозиторий. Решение: содержимое `workspace/` игнорируется гитом, в репозитории остаётся только описание папки.

**Переименования внутри `internal/` не делаю.** Предложение предлагает переименовать рабочие файлы (00–04). Это ломает ссылки в файлах состояния и в правилах репозитория, а выгода только косметическая. Имена оставляю, при необходимости поменяю одной командой позже.

**Двух версий методики быть не должно.** `METHODOLOGY.md` становится единственной публичной теорией, а `internal/draft/07_assistant_method.md` после переноса превратится в пометку о том, куда переехало содержимое. Иначе мы получим два расходящихся текста.

## 4. Итоговая структура

```
README.md                      вход: что это, зачем, как запустить за три шага
AGENTS.md                      правила: роли, уровни доказательности, маршрутизация, зоны
METHODOLOGY.md                 чистая теория: методика и пайплайн
skills/
  00-onboarding-interview/     интервью из пяти вопросов, профиль, узкое место
  01-field-filter/             отсев ниш по фильтру непроверяемости
  02-hadi-hypothesis/          гипотеза по формуле, критерий подтверждения
  03-prevalidation/            задание внешнему валидатору-ИИ
  04-mvp-artifact/             сборка артефакта-предлога
  05-validation-gate/          разговор, обязательства, статусы
templates/                     только чтение: profile, activity-map, hadi-tracker, research-queue
workspace/                     единственное место записи данных человека, не коммитится
internal/                          внутренняя кухня стрима: карта, решения, черновик речи, книги, выжимки
```

## 5. Порядок работ

1. Зоны и правила репозитория, шаблоны, песочница. **Сделано в этом шаге.**
2. Навыки 01–05 и переименование нулевого навыка под общую нумерацию.
3. Сборка `METHODOLOGY.md` из методики и пайплайна, перенос содержимого.
4. Очередь внешнего исследователя: десять заданий со ссылками и цифрами.
5. Гипотезы образов и промт для агента, собирающего презентацию.
