# Заказ 04. Внешнее исследование и карточки знаний

Все задачи этого заказа требуют внешних сервисов. Отправляет человек; агент/исполнитель только составляет файлы и разбирает ответы. Сеть из набора не используется.

## D1. Перезапустить десять запросов с требованием ссылок

Почему: ответы получены, но в них нет адресов; правило набора «нет ссылки — нет находки» не выполнено. Карточки по таким ответам не создаются.

| 2 | `req_00b_rates` | ссылки на прайсы/тарифы с датой проверки |

Требования к новым запросам (по `templates/request-short.md` или `request-full.md`):

- Категория: `быстрая` для 5 вопросов и меньше, `дип` для 6–15; один канал — `быстрая`, два и больше — `дип`.
- Один пакет — не больше шести вопросов; нумерация в каждом пакете своя от `Q1.1`; номер пакета в шапке «Пакет: N из M».
- В каждом вопросе явно: «для каждого факта — источник (URL) и дата обращения; без источника факт не засчитывается».
- Файл-запрос чистый: без гипотезы и без подсказки желаемого ответа.

Куда вернуть: `internal/draft/responses/` (у проекта) или `workspace/responses/inbox/` (у пользователя), имя файла = имя запроса + дата. Разобрать: каждый `Q` с URL и датой. Обновить архив ответов и `knowledge/INDEX.md` (статус «ответ получен, ссылки есть»).

Приёмка: `python scripts/verify_research.py` → 0; у каждого `Q` в ответе есть `https://` и дата `дд.мм.гггг`; для `дип` — два и больше файлов ответов.

## D2. Две карточки знаний из уже полученных ответов

Есть ответы со ссылками, из них можно собрать карточки без новых запросов:

1. `req_01e_depth` — 41 ссылка. Тема: глубина предвалидации/ресёрча.
2. `req_01f_failures` — 17 ссылок. Тема: типовые провалы и как их распознать.

Что сделать:

- Скопировать шаблон `templates/knowledge-card.md`, заполнить: `id`, `type`, `evidence_level: [внешнее]`, `source_url` — «ответ внешнего исследователя от <дата>» (без пути `internal/`), `date_verified`, `freshness_ttl` (6 или 12 месяцев для рыночных данных, `forever` для методик), `used_in_skills`.
- Тело карточки: 5–9 тезисов, у каждого ссылка и дата в тексте. Никаких утверждений без ссылки.
- Зарегистрировать в `knowledge/INDEX.md`: файл, тип, зачем нужна, какой шаг использует.
- В `knowledge/INDEX.md` снять строки «ждёт повторного прохода» для использованных ответов; для остальных — оставить.

Приёмка: `python scripts/verify_knowledge.py` → 0 (паспорт, срок годности, совпадение с индексом); карточки не ссылаются на `internal/`; в каждой карточке есть минимум 5 ссылок с датами.

## D3. Обновить статусы в индексе

- Факт: `knowledge/INDEX.md` содержит строки «ждёт повторного прохода» (5–7 штук) и пункт «задание 11».
- Нужно: для каждого — одна из трёх записей: «готова, карточка <id>», «ответ получен, ссылки есть, карточка не собрана», «запрос не исполнен, в очереди». Без номеров вопросов без адресата.
- Приёмка: `python scripts/verify.py` → 0; grep `ждёт` по индексу объясняет, что именно ждёт.

## Чего не делать

- Не выдумывать ссылки и даты; отсутствие источника — «не исследовано», а не «примерно так».
- Не смешивать чужие ответы: один запрос — один файл ответа.
- Не создавать карточку из ответа без ссылок — это нарушит правило набора.
