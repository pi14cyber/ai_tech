# Карта навыков: этап маршрута → навык

**Зачем файл.** Владелец 19.10.2026: «методика это концентрация моего опыта, нам надо внимательно собрать актуальные скилы — которые касаются каждого этапа». Здесь один список: какой этап каким навыком закрыт, чем именно он владеет и где ещё дырка.

**Правило маршрута:** агент загружает только тот навык, который нужен на текущем шаге. Одна большая инструкция не работает: она либо не читается, либо применяется не к месту.

## 1a. Мета-навыки: второй уровень

Владелец 20.10.2026 спросил, есть ли деление на мета-навыки и навыки. До этого ответа: нет. Понятие «мета-навык» встречалось только в разборе чужого набора (`research-notes/founder-playbook.md:197` — там `skills/diagnose` выбирает, какой фреймворк применить, и умеет самоограничиваться). Теперь уровень введён явно:

| Уровень | Что это | Где |
|---|---|---|
| **Навык этапа** | процедура одного шага маршрута | `skills/00`–`05` |
| **Мета-навык** | умение, применимое на любом шаге | `skills/m1-repo-search` |

| Мета-навык | Состояние | Зачем |
|---|---|---|
| `m1-repo-search` | **написан** | поиск готового решения под конкретную задачу пользователя: операционная формулировка, триаж, проверка чтением, запись с коммитом, решение взять/взять приём/отклонить |
| `m2-work-router` | **написан** | выбор следующего действия по состоянию проекта, а не по номеру шага; таблица веток, включая сбой упаковки против сбоя поля; правило «файл не доказывает, что этап закрыт» |
| `m3-judge` | **написан** | отдельный проход проверки перед показом: непроверенные утверждения, подмены, числа, скрытое «не проверено», поведение против сборки, границы приватности |

**Правило разделения.** Мета-навык не отменяет этапный: он определяет, что делать, а этапный — как именно. Загрузка остаётся по потребности: на шаге поля грузится `01`, а `m1` — только когда в этом шаге появилась задача «найти готовое».

## 2. Что осталось

Дырок по навыкам больше нет: каждый этап маршрута закрыт своим навыком, плюс три мета-навыка. Осталось то, что зависит не от навыков:

| Что | Состояние | Чем закрывается |
|---|---|---|
| Банки вопросов на этапы (артефакт, разговор) | не написаны | идея из разбора `KhazP`, ложится в `04` и `07` |
| Названия инструментов для `08-documents` | заблокировано | нужен полный проход по заданию 11 с прямыми адресами; определения по памяти не пишутся |
| Наполнение `knowledge/02_external` | ноль карточек с адресами | 29 ответов исследователя без ссылок: сначала повторный проход, потом карточки |
| Шесть пустых заготовок ответов в `inbox` | ждут заполнения | `req_01b`–`req_01f`, `req_02_access` |

**Нумерация.** Шаги 3 и 4 не могли получить номера `03` и `04`: они заняты воротами предвалидации и артефактом. Новые навыки продолжают нумерацию набора: `06-access`, `07-conversation`, `08-documents`, `09-audit`; мета-навыки идут с префиксом `m`.

Аудит пайплайна по источникам — `internal/draft/22_pipeline_gap_audit.md`; манифест клонов и практики — `internal/draft/24_cloned_tooling.md`.

## 4. Как проверяется

```
python scripts/verify_skills.py   # шапка, имя равно папке, размер
```

Правило навыка: никаких абстракций вроде «будь скептиком». Каждое правило — проверяемое действие или жёсткое стоп-условие (`internal/draft/10_skills_engineering.md`).
